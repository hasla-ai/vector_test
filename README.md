- **Package Manager**: [uv](https://github.com/astral-sh/uv)
- **Data & ML Libraries**: `pandas`, `numpy`, `scikit-learn`, `matplotlib`, `ucimlrepo`

- 분야: 제조
- 데이터셋(`dataset_1-1.py`): UCI Wine Quality # direct URL download, 로컬파일: 
- 사용 방식: `ucimlrepo.fetch_ucirepo(id=186)`
- 출처: https://archive.ics.uci.edu/dataset/186/wine+quality

 - 제조 품질: 와인 제조사 품질관리팀은 생산 샘플마다 산도·당도·알코올 같은 이화학 값을 여러 개 측정해 기록합니다. 값이 여러 개이므로 샘플 하나를 숫자 하나로는 표현할 수 없고, "측정값 묶음" 단위로 다뤄야 합니다. 와인 샘플별 이화학 측정값(산도, 당도, 알코올 등)을 특성 벡터로 보고 노름과 정규화를 계산합니다.

 - 품질관리팀은 샘플마다 측정 항목이 10개가 넘어 한눈에 비교하기 어렵습니다. 각 샘플의 측정값 묶음이 전체적으로 얼마나 큰지를 숫자 하나로 요약할 수 있으면 이상 샘플을 빠르게 걸러낼 수 있습니다. 노름을 계산해 벡터의 크기를 재고, 크기 차이를 없앤 뒤 방향만 비교할 수 있도록 정규화합니다.

 - - 정규화는 벡터를 자기 노름으로 나누는 연산이므로 **크기는 1로 통일되고 방향은 그대로** 유지됩니다. 크기가 제각각인 샘플들을 같은 길이로 맞추면, 이후 비교에서 "얼마나 큰가"가 아니라 "어떤 성향인가"만 남게 됩니다.

## ** 1장 3강: 행렬곱과 완전연결층 ** ##

- 분야: 마케팅
- 데이터셋(`dataset_1-3.py`): UCI Bank Marketing
- 사용 방식: `ucimlrepo.fetch_ucirepo(id=222)`
- 출처: https://archive.ics.uci.edu/dataset/222/bank+marketing
- 사용 목적: 고객별 수치형 특성(나이, 잔액, 통화 시간 등)을 데이터 행렬 X로 만들고,  완전연결층 layer를 두 개를 비교하여 고객의 파라미터가 어떻게 변하는지 검토하였음.

- 은행 마케팅팀은 텔레마케팅 대상 고객마다 "가입 가능성 점수"를 계산해 우선순위를 정하려 합니다. 고객을 한 명씩 반복문으로 계산하면 데이터가 커질수록 느려지므로, 고객 전체를 하나의 데이터 행렬로 묶어 행렬곱 한 번으로 처리해야 합니다. 이 계산 구조가 신경망의 완전연결층 y = XW + b와 정확히 같습니다.

- shape 오류를 진단하고 전치로 해결: 행렬곱 조건이 맞지 않아 생기며, 축의 의미를 되짚어 보면 대부분 전치로 해결됩니다. 오류 메시지를 출력하고, 앞서 출력한 두 shape과 대조해 어떤 차원이 맞지 않는지 확인합니다. numpy 버전에 따라 오류 메시지가 전체 shape을 다 알려주지 않을 수 있으므로, 오류를 만나기 전에 관련 배열들의 shape을 직접 출력해 비교하는 습관이 실무에서도 더 안정적인 디버깅 방법입니다.

- 추가적으로, 실제 모델은 완전연결층 하나로 끝나지 않고 여러 층을 이어 붙입니다. 2층 구조의 shape 흐름과 파라미터 수 계산하기를 시행합니다. 층을 쌓을 때마다 출력 차원이 다음 층의 입력 차원이 되므로, shape 흐름을 정확히 추적하지 못하면 모델을 조립할 수 없습니다. 은닉층을 하나 추가해 데이터가 어떤 shape으로 흘러가는지 확인합니다.

- 은닉 차원을 키우면 출력 shape은 그대로지만 파라미터 수는 크게 늘어납니다. 모델 용량과 계산 비용을 조절하는 지점이 바로 이 은닉 차원입니다.

## ** 1장 4강 - 실습: 특수 행렬과 행렬 연산 성질 ** ##

- 분야: 금융
- 데이터셋(`dataset_1_4.py`): UCI Default of Credit Card Clients
- 사용 방식: `ucimlrepo.fetch_ucirepo(id=350)`
- 출처: https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients
- 사용 목적: 신용카드 고객의 수치형 특성으로 데이터 행렬을 만들어 대칭행렬(`XᵀX`)과 행렬식을 확인합니다.

 - (가상) 리스크 분석팀은 신용 점수 모델에서 특정 항목(예: 연체 이력)의 비중을 키우고 다른 항목의 비중을 줄이는 실험을 하려 합니다. 이때 항목별 가중치를 대각행렬로 표현하면 행렬곱 한 번으로 축별 비중을 조정할 수 있습니다. 먼저 "곱해도 아무것도 바꾸지 않는" 단위행렬을 기준점으로 두고, 대각행렬과 대칭행렬의 성질을 확인합니다.

 - 리스크 모델에서는 "표준화 후 가중치 적용"과 "가중치 적용 후 표준화"처럼 처리 순서를 바꿔 실험하는 일이 잦습니다. 숫자의 곱셈과 달리 행렬 곱은 순서를 바꾸면 결과가 달라지므로, 순서를 바꾼 실험은 다른 처리로 취급해야 합니다. 이 성질을 직접 확인하고, 전치를 취할 때 순서가 뒤집히는 이유까지 이어서 살펴봅니다.

 - 리스크 모델을 학습할 때 XᵀX의 역행렬이 필요한 경우가 있습니다. 그런데 데이터에 사실상 중복인 컬럼(예: 월 소득과 연 소득)이 섞여 있으면 역행렬 계산이 불안정해지고, 계수 값이 비정상적으로 커지거나 실행할 때마다 달라집니다. 
  월 소득이 있으면 연 소득은 새로운 정보가 전혀 없는 100% 겹치는 정보입니다. 선형대수학에서는 이를 선형 종속(Linear Dependence) 또는 완벽한 다중공선성이라고 부릅니다.
  이런 중복 데이터가 들어가면 수학적으로 다음과 같은 문제가 터집니다.
  1) 독립적인 정보가 늘어나지 않음: 변수는 5개가 되었지만 실제 유용한 정보의 축(Rank)은 여전히 4개입니다.
  2) 역행렬 연산 불가: $X_{dup}^T X_{dup}$ 행렬의 행렬식($\text{det}$)이 0이 되어 역행렬을 구하는 것이 수학적으로 불가능(Singular Matrix)해집니다.

  데이터에 완벽히 겹치는 가짜 피처를 일부러 1개 섞어서 선형대수 연산(역행렬)이 어떻게 고장 나는지 눈으로 확인해 보는 실험을 하여(중복 칼럼 삽입), 행렬식과 조건수를 함께 확인해 이 위험을 미리 감지합니다.

 - 행렬식이 0에 수렴하거나 조건수(Condition Number)가 급격히 발산하면 선형 회귀 등의 역행렬 계산 시 수치적 불안정성으로 인해 가중치 추정값이 폭발하게 됩니다.이때 행렬식의 절댓값 크기 자체는 데이터 단위 스케일 변화에 의해 왜곡되므로 역행렬의 안정성을 판단하는 절대적 기준이 될 수 없으며, 스케일에 독립적인 조건수를 핵심 지표로 활용해야 합니다.실무에서는 완벽한 선형 종속성을 갖는 다중공선성 피처를 제거(또는 VIF 체크)하거나, 대각선에 규제항을 더해주는 Ridge 정칙화($(X^T X + \lambda I)^{-1}$) 혹은 PCA 차원 축소를 적용하여 수치 안정성을 확보합니다.

## ** 2장 1강 - 실습: 선형 변환의 기하학적 해석 ** ##

- 분야: 헬스케어
- 데이터셋(`dataset_2_1.py`): UCI Breast Cancer Wisconsin (Diagnostic)
- 사용 방식: `ucimlrepo.fetch_ucirepo(id=17)`
- 출처: https://archive.ics.uci.edu/dataset/17/breast+cancer+wisconsin+diagnostic
- 사용 목적: 진단 특성 2개를 좌표평면 위의 점으로 보고, 2×2 변환 행렬이 데이터 분포를 어떻게 움직이는지 관찰합니다.

- (가상) 의료 데이터 시각화 담당자는 두 진단 지표의 산점도를 보고서에 넣으려 합니다. 축 비율을 조정하거나 축을 뒤집는 등 표현 방식을 바꿔야 하는데, 이런 조정은 모두 2×2 행렬 하나를 곱하는 선형 변환으로 표현됩니다. 각 변환 행렬이 분포를 어떻게 바꾸는지 직접 확인합니다.

  반사는 모든 벡터의 길이(노름)를 보존하고 역행렬이 존재하여 완전한 원본 복원이 가능한 등거리 변환인 반면, 투영은 특정 차원의 정보를 0으로 찌그러뜨려 서로 다른 점들을 하나의 점으로 겹치게 만들므로 역행렬이 존재하지 않고 정보가 영구히 손실됩니다.

- 기하학적으로 이렇게 "서로 다른 여러 점이 한 점으로 모이는" 상황이 곧 차원이 줄어든다는 의미이고 이를 활용하는 방법을 생각해보게 되었습니다.

- (가상) 시각화 담당자가 "데이터를 45도 돌린 다음 x축 방향으로 늘려 달라"는 요청과 "늘린 다음 돌려 달라"는 요청을 각각 받았습니다. 두 요청이 같은 결과를 낼 것 같지만, 행렬 곱은 순서를 바꾸면 결과가 달라집니다. 회전 행렬을 만들고 합성 순서에 따른 차이를 확인합니다.

필수 1. 품질 측정 기록을 벡터로 다루기

문제 1-1 스칼라. 벡터. 행렬의 구분

**요구 사항**

1. `X`에서 첫 번째 샘플의 측정값을 `v1`(NumPy 배열)로 추출합니다.
2. `X` 전체 표, `v1`, `v1`의 첫 번째 원소를 각각 출력하고 `shape`(또는 값)을 확인합니다.
3. 세 대상이 각각 행렬·벡터·스칼라 중 무엇인지, 분석에서 어떤 역할을 하는지 한 문장씩 설명합니다.

**출력 결과**
  - 데이터 행렬의 shape과 특성 벡터의 shape
  - 스칼라 값 1개
  - 세 대상의 역할 구분 설명

```bash
=== [1장-1강-필수1] 문제 1-1 출력 결과 ===
```

문제 2-1 L1·L2·L∞ 노름 계산하기
  - **요구 사항**

1. `v1`에 대해 L1 노름, L2 노름, L∞ 노름을 각각 계산합니다.
2. L2 노름은 `np.sqrt(np.sum(v1 ** 2))`로도 직접 계산해 `np.linalg.norm(v1, 2)`와 값이 같은지 확인합니다.
3. 세 노름이 각각 무엇을 크게 반영하는지 비교해 한 문장으로 설명합니다.

- **출력 결과**
    - L1, L2, L∞ 노름 값
    - 직접 계산한 L2와 라이브러리 결과 일치 여부
    - 세 노름의 차이 설명

```bash
=== [1장-1강-필수2] 문제 2-1 출력 결과 ===
1. L1 노름 (L1 Norm)   : 69.5438
2. L2 노름 (L2 Norm)   : 37.9191 (직접 계산: 37.9191, 일치 여부: True)
3. L∞ 노름 (L∞ Norm)   : 34.0000

=== [세 노름의 특징 비교 설명] ===
L1 노름은 모든 성분의 절대값 합으로 전체적인 스케일의 총량을 평등하게 반영하고, L2 노름은 제곱합의 제곱근으로 기하학적 직선 거리를 반영하며, L∞ 노름은 성분 중 가장 큰 최대 절대값을 집중적으로 반영합니다.
```
- L1은 성분의 절댓값을 모두 더하므로 **작은 값들의 누적**까지 반영합니다.
- L2는 제곱해서 더하므로 **큰 성분의 영향이 커지고**, 피타고라스 정리를 확장한 유클리드 거리와 같은 값입니다.
- L∞는 **가장 큰 성분 하나**만 보므로, 특정 항목이 튀는 샘플을 잡아낼 때 유용합니다.

```bash
=== [1장-1강-필수2] 문제 2-2 출력 결과 ===
1. 단위벡터 u1의 L2 노름: 1.0000 (1.0 일치 여부: True)

2. 앞 5개 샘플의 정규화 전후 노름 비교 표:
 샘플(ID)  정규화 전 L2 노름  정규화 후 L2 노름
      0    37.919060          1.0
      1    72.733211          1.0
      2    57.582999          1.0
      3    64.232434          1.0
      4    37.919060          1.0

=== [정규화의 의미 설명] ===
정규화는 벡터의 방향(각 성분 간 상대적 비율)을 유지하면서, 크기(L2 노름)를 항상 1로 통일하여 크기 차이에 따른 왜곡 없이 순수한 성분 조합 형태를 비교할 수 있게 합니다.
```
 - 정규화는 벡터를 자기 노름으로 나누는 연산이므로 **크기는 1로 통일되고 방향은 그대로** 유지됩니다.
 - 크기가 제각각인 샘플들을 같은 길이로 맞추면, 이후 비교에서 "얼마나 큰가"가 아니라 "어떤 성향인가"만 남게 됩니다.
